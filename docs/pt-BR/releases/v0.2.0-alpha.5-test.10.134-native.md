# OMSI Map Studio v0.2.0-alpha.5-test.10.134-native

## Test 10.134 — preferência por junction stock com controle semafórico OMSI funcional

A Test 10.132 passou a posicionar semáforos e travessias stock a partir do OSM. A Test 10.134 melhora a própria escolha do cruzamento original: quando o OSM indica que a interseção é semaforizada, o resolver passa a preferir um junction stock que já possua a lógica semafórica nativa do OMSI.

### O que é considerado controle funcional

Um candidato stock é marcado como funcional quando o próprio `.sco` contém:

- controlador/programa OMSI em `[traffic_lights_group]` / `[traffic_light]` / `[phase]`;
- pelo menos um path veicular tipo `0` ligado a esse controle por `[use_traffic_light]`.

Não é criado um formato paralelo. A leitura usa o parser OMSI existente do Map Studio.

### Seleção

A compatibilidade geométrica continua obrigatória:

- mesma quantidade de braços;
- tolerância angular máxima preservada;
- largura compatível;
- boca/trim fisicamente válido.

Somente entre candidatos que já passaram esses requisitos, um target OSM semaforizado dá preferência ao asset com controle funcional interno.

Se nenhum junction funcional for compatível, o comportamento anterior continua: usa outro junction stock geometricamente compatível e mantém os semáforos stock externos da reconstrução; junction gerado continua sendo fallback final.

### Propagação OSM

Os nós `highway=traffic_signals` e travessias com sinalização são associados ao junction do grafo mais próximo. Esse junction recebe `PreferFunctionalTrafficControl=true` antes da resolução dos assets.
