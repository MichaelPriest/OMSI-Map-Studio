# OMSI Map Studio v0.2.0-alpha.5-test.10.143-native

## Test 10.143 — recuperação robusta do OpenStreetMap

Esta versão corrige a falha observada quando a camada **Vias** recebe timeouts/HTTP 503 de vários servidores Overpass ao mesmo tempo.

### O que mudou

- cada bloco agora pode tentar **todos os endpoints Overpass configurados** antes de desistir;
- um timeout em um bloco grande não coloca mais o endpoint em cooldown rígido antes de tentar os blocos menores de recuperação;
- respostas `429 Too Many Requests` continuam respeitando `Retry-After` e cooldown real;
- quando somente parte de uma camada falha, o downloader executa até **duas passagens extras de recuperação**;
- nessas passagens, os chunks que já foram baixados são reaproveitados do cache e somente as partes faltantes voltam para a rede;
- o fallback da API principal do OpenStreetMap continua ativo;
- a reconstrução continua transacional: a camada Vias só é aceita quando toda a cobertura necessária foi validada.

### Por que isso resolve o caso da captura

O erro mostrava uma combinação de timeout em `overpass-api.de` / `overpass.private.coffee` e HTTP 503 no fallback `api.openstreetmap.org`. Antes, um timeout também colocava o endpoint temporariamente fora da rotação, justamente quando a recuperação subdividia o bloco. Isso podia deixar os filhos sem um servidor saudável disponível.

Agora o timeout reduz a prioridade daquele servidor, mas os chunks menores ainda podem reutilizá-lo. Se a indisponibilidade for transitória, a passagem automática de recuperação reaproveita o que já está no cache e tenta apenas os pedaços que faltaram.

### Regressões novas

- uso de todos os endpoints configurados antes de subdividir;
- recuperação de um timeout do bloco pai por meio de filhos menores;
- manutenção da proteção de `Retry-After`;
- cache persistente continua sendo reutilizado sem nova requisição.
