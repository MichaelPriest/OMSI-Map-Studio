# OMSI Map Studio v0.2.0-alpha.5-test.10.74-native

## Test 10.74 — portais automáticos nas entradas e saídas de túneis

Esta preview inicia o fechamento visual das transições estrada ↔ túnel.

- runs contínuos resolvidos como **túnel**, inclusive quando o OSM informa apenas `layer < 0`, agora têm as extremidades detectadas automaticamente;
- cada run recebe um portal no início e outro no fim, sem criar um portal a cada segmento interno;
- a largura do portal acompanha o perfil físico do Road Kit e é quantizada para permitir reuso de assets;
- o portal usa SCO/O3D real gerado pelo próprio Map Studio;
- a geometria contém pilares laterais, viga superior e alas curtas para esconder a transição seca entre terreno e estrutura;
- a textura procedural `ms_tunnel_concrete.bmp` não depende de assets externos;
- orientação considera retas e curvas para manter o portal perpendicular ao eixo da via;
- túneis inferidos somente por `layer` usam o mesmo fluxo;
- pontes não recebem portais;
- nenhuma alteração é feita em arquivos `.terrain`;
- os portais são persistidos automaticamente no mesmo fluxo de geração das vias, após as splines/pilares e antes das junctions;
- a inserção usa batches reais de scenery objects, com reutilização de asset e backup separado por lote;
- falha em um portal não desfaz as splines de rua já persistidas e fica registrada no diagnóstico;
- testes Core e Renderer validam geometria, detecção das duas extremidades, reuso de asset e preservação do terreno.

Próximo passo: ampliar as paredes/estrutura do túnel até o portal e melhorar a integração com o terreno para eliminar a emenda visual restante.
