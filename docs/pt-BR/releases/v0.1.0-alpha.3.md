# OMSI Map Studio v0.1.0-alpha.3

Terceira prerelease testável do OMSI Map Studio, agora com edição preservativa experimental.

## Destaques

- mapa completo como modo padrão, com modo desempenho 3×3 opcional;
- interface React no host desktop, consumindo estado real do C#;
- objetos `.sco` e geometria O3D reais carregados progressivamente;
- seleção, mover, rotacionar e edição numérica de X/Y/Z/rotação/pitch/bank;
- prévias não salvas com desfazer/refazer e descarte;
- salvamento preservativo de transformações com releitura do tile, detecção de conflito, backup e troca atômica;
- splines reais com leitura de `.sli`, perfil `[profile]` / `[profilepnt]`, extrusão de prévia, edição persistente numérica, gizmos W/E, criação por cópia desconectada e exclusão transacional de splines desconectadas ou conectadas;
- edição transacional de vínculos `previous/next`, atualizando reciprocamente vizinhos antigos/novos e gravando múltiplos tiles com rollback;
- Biblioteca real de `Splines` com busca sob demanda e criação segura Normal/Altura a partir de `.sli` instalado quando existe template neutro real do mesmo tipo;
- Biblioteca real de `Sceneryobjects` com busca sob demanda;
- colocação de objetos com prévia real e persistência segura quando existe template compatível do mesmo `.sco`;
- **Colocar cópia** para reutilizar o `.sco` do objeto selecionado, preservando inicialmente Z/rotação/pitch/bank e escolhendo novo X/Y no viewport;
- exclusão persistente segura de objetos com validação por ordinal + ID + `.sco`, confirmação e backup automático;
- geração de novo ID global considerando objetos, attachments e splines;
- ícone próprio do aplicativo.

## Segurança de gravação

A Alpha.3 não reserializa o tile inteiro para salvar uma transformação ou inserir um objeto. O host reabre o arquivo atual, valida a identidade do elemento, preserva seções/comentários desconhecidos, cria backup em `.mapstudio-backups/<timestamp>/` e usa substituição atômica.

## Limitações atuais

- criação por arquivo instalado exige template neutro real do mesmo tipo no mapa;
- inserção persistente de um `.sco` nunca usado no mapa continua bloqueada quando não há template seguro;
- terreno binário `.terrain` ainda não é interpretado;
- texturas reais O3D e de perfis de spline carregadas sob demanda para seleção/prévias, com BMP/PNG/JPG/GIF/WebP/DDS/TGA e limite de 16 MiB;
- mapas `[worldcoordinates]` continuam limitados para edição.

Consulte `docs/pt-BR/TESTING.md` para o roteiro de validação.


### Prefetch de texturas

- texturas reais também são preenchidas progressivamente para recursos próximos ao tile ativo;
- orçamento automático de 16 texturas O3D + 8 texturas de spline;
- perfis `.sli` próximos são preparados sequencialmente;
- seleção/prévia mantém prioridade fora do orçamento automático;
- barra de status expõe o uso `X/24`.


### Overrides de material SCO

- leitura preservando mesh ordinal para `[matl]` estático;
- `[matl_alpha]` 0/1/2 aplicado como opaco/cutout/blend;
- `[matl_noZwrite]` e `[matl_noZcheck]` aplicados no Babylon;
- `[matl_change]` deliberadamente não é congelado como estado estático;
- inspetor de materiais mostra o override SCO efetivamente associado.


### Bumpmap

- `[matl_bumpmap]` estático lido por material SCO;
- textura real carregada pelo resolver seguro existente;
- fator explícito aplicado ao `bumpTexture.level` do Babylon;
- estado/nome/fator visíveis no inspetor.


### Nightmap

- `[matl_nightmap]` estático por material;
- camada manual **Nightmap** no viewport;
- carregamento somente quando ativada para seleção/prévia e dentro do orçamento automático para o mapa;
- sem simulação fake de horário/scripts.
