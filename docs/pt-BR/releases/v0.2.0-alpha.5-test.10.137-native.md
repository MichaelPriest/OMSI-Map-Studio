# OMSI Map Studio v0.2.0-alpha.5-test.10.137-native

## Test 10.137 — placas explícitas de velocidade máxima

A Test 10.137 amplia a sinalização automática sem inventar posição de placas. O Map Studio passa a reconhecer nós OSM que representam fisicamente uma placa de limite de velocidade e só gera o objeto quando o valor exibido está explícito e existe um asset instalado compatível.

### Evidência aceita

São reconhecidos nós de placa com:

- `traffic_sign=maxspeed` + `maxspeed=50`;
- `traffic_sign=BR:R-19` + `maxspeed=60`;
- `traffic_sign=BR:R-19[30]`.

O valor é normalizado internamente para uma referência como `maxspeed 50`.

### Regras conservadoras

Não é gerada placa apenas porque uma way possui `maxspeed=*`. O limite da via é útil para regra de tráfego, mas não informa sozinho a posição física exata do sinal.

Também permanecem fora da geração automática:

- `maxspeed=implicit`;
- valores não numéricos;
- listas de velocidades;
- unidades incompatíveis como mph;
- valores sem direção resolvida.

### Correspondência com assets

O asset instalado precisa:

1. pertencer à família de sinalização;
2. parecer uma placa de velocidade (`274`, `tempo`, `speed`, `geschw`, `maxspeed` ou R-19);
3. conter exatamente o mesmo valor numérico.

Exemplo: `maxspeed 30` pode selecionar `VZ_274_30.sco`, mas `maxspeed 50` não pode cair nesse mesmo asset.

### Round-trip

A regressão cria `VZ_274_30.sco` e `VZ_274_50.sco`, injeta um nó OSM `traffic_sign=maxspeed + maxspeed=50 + direction=90`, executa o batch runner e relê `tile_0_0.map`.

O resultado obrigatório é `VZ_274_50.sco` com rotação de aproximadamente 90 graus.

### Regressões preservadas

Continuam cobertos R-1/R-2 brasileiros, R-3 rejeitado, STOP/GIVE_WAY, orientação por way, direção ambígua em revisão, cache OSM v3 e todos os gates anteriores.
