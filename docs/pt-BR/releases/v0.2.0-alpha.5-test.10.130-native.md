# OMSI Map Studio v0.2.0-alpha.5-test.10.130-native

## Test 10.130 — cruzamentos originais OMSI encaixados pela geometria real

A Test 10.129 passou a reconhecer as famílias originais do OMSI 2. Esta build dá o passo seguinte: cruzamentos stock de `Kreuz_MC` e `Kreuz_RUE` podem ser usados automaticamente quando seus paths reais são compatíveis com a topologia do OpenStreetMap.

### Como o encaixe funciona

- o editor abre o `.sco` instalado e lê os `[path]` veiculares reais;
- calcula início/fim inclusive para paths curvos com raio;
- identifica as bocas externas do cruzamento e agrupa as faixas de uma mesma boca;
- compara quantidade de braços, ângulos e largura aproximada com o nó viário OSM;
- calcula a rotação necessária do `.sco`;
- rejeita o asset se qualquer braço passar do limite angular de segurança;
- rejeita o asset se as larguras forem incompatíveis;
- rejeita o asset se a boca exigir cortar uma parte excessiva do segmento conectado.

### Encaixe físico das splines

Quando um cruzamento stock é aceito, as splines não continuam até o centro do objeto. O Map Studio usa a distância real das bocas do `.sco` para encurtar os segmentos conectados, reproduzindo o modo como crossings do OMSI são montados no editor original.

Se o cruzamento stock não passar por todas as verificações, a junction procedural do Map Studio continua sendo gerada como fallback.

### Casos cobertos

- cruzamento de quatro braços;
- entroncamento/T de três braços;
- rejeição de asset com quantidade de braços incompatível;
- rotação automática;
- múltiplas faixas por boca;
- gravação do `.sco` original no tile;
- leitura de volta do tile confirmando o asset;
- verificação de que as splines foram realmente encurtadas.

A geração automática também informa separadamente quantos cruzamentos foram montados com assets stock do OMSI e quantos precisaram do fallback gerado.
