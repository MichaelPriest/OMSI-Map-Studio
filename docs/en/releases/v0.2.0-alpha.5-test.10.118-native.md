# OMSI Map Studio v0.2.0-alpha.5-test.10.118-native

## Test 10.118 — layered OSM acquisition, resumable cache and endpoint cooldown

Test 10.118 replaces the monolithic OSM request in the default generation path with layered acquisition, reducing pressure on public Overpass servers and preventing one large query from blocking the entire reconstruction.

### What changed

- OpenStreetMap is now downloaded in five sequential layers: **Roads**, **Buildings**, **Infrastructure**, **Vegetation** and **Furniture**;
- each layer uses its own query and chunk size instead of requesting every category in one query;
- at most two chunk requests remain active concurrently;
- each chunk tries up to two healthy Overpass endpoints before fallback;
- HTTP 429 responses honor `Retry-After` and put the server on cooldown;
- transient HTTP 408/500/502/503/504 failures use backoff before switching server;
- endpoints have a health score and cooldown so unhealthy servers are not hammered repeatedly;
- the official `https://api.openstreetmap.org/api/0.6/map` fallback remains available and is also cooldown-aware;
- completed chunks are validated and atomically cached under `<OMSI>/.mapstudio/cache/osm`;
- after cancellation, failure or a repeated generation attempt, valid completed chunks are reused without another download;
- invalid/corrupt cache files are discarded and fetched again;
- diagnostics record layer, chunk, endpoint, attempt, HTTP status, elapsed time and returned byte size;
- failures identify the exact layer and chunk that could not be completed;
- the UI receives explicit progress such as:
  - `OpenStreetMap → Vias → bloco 3/12 → servidor X → tentativa 2/2`;
  - then Buildings, Infrastructure, Vegetation and Furniture;
  - followed by map application.

### Transactional safety

All OSM layers must be downloaded and parsed before the pipeline starts changing map tiles. Transaction snapshots, rollback, zero-placement rejection, cancellation and animated loading remain enabled.

Regression coverage was added for:

- effective separation of the five queries;
- `Retry-After` and endpoint cooldown;
- persistent cache and network-free resume;
- layer/chunk failure diagnostics;
- preservation of the legacy progress contract for injected integrations.
