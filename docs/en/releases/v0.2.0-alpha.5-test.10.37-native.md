# OMSI Map Studio v0.2.0-alpha.5-test.10.37-native

Native preview focused on fixing apparently missing road sections and synthetic junctions in OpenStreetMap automatic generation.

## OSM as authoritative topology

Test 10.36 already downloaded the full area and did not skip road segments. Its diagnostics showed that all 20,215 graph segments were represented by 17,665 placements plus 2,550 native curves.

The remaining problem was graph interpretation:

- any 2D geometric crossing could become a junction;
- endpoints from different ways could be snapped/projected even without a real OSM connection;
- this created synthetic junctions at bridges, tunnels, parallel carriageways and nearby roads;
- every synthetic junction trimmed road splines and visually looked like a missing road section.

OSM traces are now marked as authoritative topology:

- different ways connect only through shared OSM node coordinates;
- a visual 2D crossing no longer creates a junction by itself;
- synthetic endpoint projection/snap between different OSM ways is disabled;
- manual and non-authoritative sources may still use automatic geometric intersections.

## Bridge, tunnel and layer

The OSM importer now reads:

- `bridge`;
- `tunnel`;
- `layer`.

These values are preserved in road traces and graph segments. For non-authoritative sources, different layers and incompatible bridge/tunnel state also prevent synthetic interior intersections.

## Lanes and direction

The importer now uses:

- `lanes`;
- `lanes:forward`;
- `lanes:backward`;
- `oneway=yes/no/-1`;
- `junction=roundabout/circular`.

When `lanes` is missing, total lanes may be inferred from the directional lane counts.

For `oneway=-1`, the geometry is reversed and forward/backward lane metadata is swapped so traffic direction remains physically correct.

The selected Road Kit profile remains the final physical geometry; OSM metadata selects the best matching profile and the result is normalized to the chosen asset.

## Junction paths

Each junction arm now keeps separate:

- inbound lanes;
- outbound lanes.

This fixes the previous simplified one-way handling that did not know whether a one-way arm was entering or leaving the node.

Internal junction paths are now created only:

- from arms with inbound traffic;
- toward arms with outbound traffic.

## Visual fitting

Road trimming before a junction now leaves a small controlled overlap of up to 0.45 m with the generated crossing surface.

This removes visible cracks caused by exact edge-to-edge placement, floating-point precision and width differences.

## Diagnostics

The road graph line in `startup.log` now includes:

- `authoritative=`;
- `directional=`;
- `gradeSeparated=`.

This makes it possible to verify how many OSM traces use authoritative topology, directional lane metadata and bridge/tunnel/layer metadata.
