# OMSI Map Studio v0.2.0-alpha.5-test.10.137-native

## Test 10.137 — explicit maximum-speed signs

Test 10.137 expands automatic traffic-sign reconstruction without inventing sign locations. Map Studio now recognizes OSM nodes that physically represent a maximum-speed sign and only generates an object when the displayed value is explicit and a compatible installed asset exists.

### Accepted evidence

Recognized sign nodes include:

- `traffic_sign=maxspeed` + `maxspeed=50`;
- `traffic_sign=BR:R-19` + `maxspeed=60`;
- `traffic_sign=BR:R-19[30]`.

The value is normalized internally to a reference such as `maxspeed 50`.

### Conservative rules

A sign is not created merely because a road way contains `maxspeed=*`. The road restriction is useful for traffic rules, but by itself it does not identify the physical sign location.

The following also remain outside automatic sign generation:

- `maxspeed=implicit`;
- non-numeric values;
- speed lists;
- incompatible units such as mph;
- signs without a resolved direction.

### Installed-asset matching

The installed asset must:

1. belong to the traffic-sign family;
2. look like a speed-limit sign (`274`, `tempo`, `speed`, `geschw`, `maxspeed` or R-19);
3. contain the exact same numeric value.

For example, `maxspeed 30` can select `VZ_274_30.sco`, while `maxspeed 50` cannot fall through to that same asset.

### Round-trip

The integration regression creates `VZ_274_30.sco` and `VZ_274_50.sco`, injects an OSM node with `traffic_sign=maxspeed + maxspeed=50 + direction=90`, runs the batch reconstruction, and reads `tile_0_0.map` back.

The required result is `VZ_274_50.sco` at approximately 90 degrees rotation.

### Preserved regressions

Brazilian R-1/R-2, rejected R-3, STOP/GIVE-WAY, way-derived direction, ambiguous-direction review, OSM cache v3, and all previous gates remain covered.
