# OMSI Map Studio v0.2.0-alpha.5-test.10.130-native

## Test 10.130 — original OMSI junctions fitted from real geometry

Test 10.129 added explicit recognition of original OMSI 2 asset families. This build takes the next step: stock `Kreuz_MC` and `Kreuz_RUE` junction SCOs can be used automatically when their real traffic paths are compatible with the OpenStreetMap road topology.

### Junction fitting

- Map Studio opens the installed `.sco` and reads its real vehicle `[path]` entries;
- start/end points are calculated for both straight and curved paths;
- external junction mouths are detected and multiple lanes at the same mouth are clustered;
- arm count, angles and approximate widths are compared with the OSM junction;
- the required SCO rotation is calculated;
- candidates exceeding the safe angular, width or trim limits are rejected.

### Physical spline connection

When a stock junction is accepted, connecting splines no longer run through the SCO center. Their endpoints are trimmed back to the measured junction mouths, matching the construction model used by original OMSI crossings.

If no stock junction passes every compatibility check, Map Studio keeps the procedural junction generator as a safe fallback.

### Regression coverage

Coverage includes four-arm crossings, three-arm/T junctions, incompatible arm-count rejection, automatic rotation, multi-lane mouth clustering, real tile persistence and a round-trip check proving the connecting splines were shortened.

Automatic generation progress also reports stock OMSI junction usage separately from generated fallback junctions.
