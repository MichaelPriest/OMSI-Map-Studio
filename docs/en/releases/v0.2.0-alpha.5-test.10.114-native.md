# OMSI Map Studio v0.2.0-alpha.5-test.10.114-native

## Test 10.114 — OSM download without apparent freezes

This build fixes the retry chain that could make OpenStreetMap download appear frozen for several minutes when public servers were slow or unreachable.

### Changes

- primary chunks reduced from roughly 750 m to 500 m;
- TCP/TLS connection establishment now has its own 8-second limit;
- each request attempt still has a 20-second limit;
- requests use ResponseHeadersRead so the pipeline regains control before buffering the full body;
- progress immediately reports the block, endpoint and active attempt number;
- endpoints that fail at transport/timeout level are inherited as unavailable by recovery subchunks;
- subdivision recovery no longer retries transport-dead servers that already failed;
- subdivision only runs when a server response indicates a smaller query may help, such as selected 408/429/5xx statuses;
- when no healthy endpoint remains, the block fails immediately instead of multiplying timeouts;
- two-request concurrency, user cancellation and rollback remain enabled.

### UI

The four-step wizard from Test 10.113 remains: Area, Sources, Reconstruction and Progress. During download, Progress now shows the server currently being queried, avoiding the appearance of a frozen operation.
