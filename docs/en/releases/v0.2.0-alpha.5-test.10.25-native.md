# OMSI Map Studio v0.2.0-alpha.5-test.10.25-native

Build **ALPHA 5 TEST 10.25 — exact diagnostics and isolated CARTO download path**.

## Observed problem

On some systems, **Map > Map reference over terrain...** could still fail inside `LoadCartoReferenceAsync` with:

`NullReferenceException: Object reference not set to an instance of an object.`

Test 10.24 had already hardened legacy georeference data, missing HTTP content and the WIC/PNG path, but the failure could still happen before the texture reached the viewport.

## Test 10.25 changes

- CARTO reference download now uses a **dedicated HttpClient**;
- the primary path uses `GetByteArrayAsync`, reducing reliance on intermediate `HttpResponseMessage.Content` objects;
- a second HTTP path with a fresh handler is attempted when a `NullReferenceException` occurs during download;
- the cache moved to `carto-keyed-v2` so problematic reference files from older builds are not reused;
- exact sub-stages are tracked:
  - `georeference-load`;
  - `georeference-validation`;
  - `mercator-position`;
  - `cache-path`;
  - `cache-check`;
  - `request-uri`;
  - `http-download`;
  - `http-download-fallback`;
  - `png-validation`;
  - `cache-write`;
  - `reference-metadata`;
- full CARTO exceptions are logged to:
  `%LocalAppData%\OMSI Map Studio\logs\carto-reference.log`;
- the status bar now points to that diagnostic file when CARTO reference loading fails.

## Carried forward

Still included:

- Map Studio native PNG decoder;
- hardened WIC fallback;
- CARTO key storage in Windows Credential Manager;
- OSM fallback in the area picker;
- non-pickable visual map reference;
- previous navigation, streaming and cache improvements.
