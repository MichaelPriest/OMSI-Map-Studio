# OMSI Map Studio v0.2.0-alpha.5-test.10.106-native

## Test 10.106 — more faithful OSM facades and roofs

Building reconstruction in **Real World Reconstruction** now uses OpenStreetMap appearance metadata to generate less generic OMSI assets.

### Per-building appearance

The pipeline now preserves, including for multipolygons/relations:

- `building:material`;
- `building:colour` and `building:color`;
- `roof:material`;
- `roof:colour` and `roof:color`.

These values flow from the OSM importer to the projected footprint and into the generated asset.

### Generated textures

Each building still uses its own folder under `Sceneryobjects`, while `ms_osm_facade.bmp` and `ms_osm_roof.bmp` are now generated from the building metadata.

Visual handling is included for brick, concrete, glass, stone, wood, metal, roof tiles and slate, plus hexadecimal colours and common colour names. When OSM does not provide appearance information, the generator falls back to palettes based on the building type.

The `mapstudio-osm-building.txt` manifest also records the four appearance fields for diagnostics and traceability.

### Validation

Real tests were added without mocks for:

- tag import from ways;
- tag import from relations/multipolygons;
- metadata propagation through the projector;
- deterministic facade and roof texture pixels;
- appearance metadata persisted in the generated asset manifest.
