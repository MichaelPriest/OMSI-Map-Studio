# OMSI Map Studio v0.2.0-alpha.5-test.10.74-native

## Test 10.74 — automatic portals at tunnel entrances and exits

This preview starts closing the visual road ↔ tunnel transition.

- continuous runs resolved as **tunnel**, including OSM data that only provides `layer < 0`, now have their endpoints detected automatically;
- each run receives one portal at the beginning and one at the end instead of one portal per internal segment;
- portal width follows the physical Road Kit profile and is quantized so generated assets can be reused;
- portals are real SCO/O3D assets generated by Map Studio;
- geometry includes side piers, a top beam and short wing walls to hide the abrupt terrain/structure seam;
- procedural `ms_tunnel_concrete.bmp` texture adds no external asset dependency;
- orientation follows straight and curved road geometry so the portal remains perpendicular to the road axis;
- layer-only tunnels use the same flow;
- bridges do not receive portals;
- no `.terrain` file is modified;
- Core and Renderer tests validate geometry, both run endpoints, asset reuse and terrain preservation.

Next step: persist/insert the portals together with the automatic generation batch and extend tunnel walls/structure all the way into the portal to remove the remaining visual seam.
