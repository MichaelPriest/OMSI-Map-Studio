# OMSI Map Studio v0.2.0-alpha.5-test.10.138-native

## Test 10.138 — stricter R-19 / maximum-speed matching

Test 10.138 preserves the explicit maximum-speed sign generation introduced in 10.137 and hardens two comparisons to prevent false-positive asset matches.

### Exact Brazilian code

Only these forms are treated as R-19:

- `BR:R-19`;
- `BR:R-19[<speed>]`.

A code that merely starts with the same characters, such as `BR:R-190`, is not reinterpreted as a maximum-speed sign.

### Exact asset family

German `274` family matching now requires the exact numeric token as well.

Therefore:

- `VZ_274_50.sco` can satisfy `maxspeed 50`;
- `VZ_1274_50.sco` cannot be mistaken for family `274`;
- the displayed speed value must still match exactly.

Recognized textual families (`tempo`, `speed`, `geschw`, `maxspeed`) and explicit R-19 asset names remain eligible.

### Regression coverage

The Test 10.138 gate preserves:

- `traffic_sign=maxspeed` parsing;
- `BR:R-19[30]`;
- `BR:R-190` remaining non-canonical;
- `maxspeed=implicit` review fallback;
- exact `VZ_274_30` matching;
- rejection of `VZ_1274_50` as family 274;
- `VZ_274_50` OMSI tile round-trip;
- Brazilian R-1/R-2 and all previous gates.
