# OMSI Map Studio v0.2.0-alpha.5-test.10.119-native

## Test 10.119 — drivable-road filtering and anti-spaghetti spline guard

Test 10.119 addresses the real 10.118 run where OSM acquisition succeeded but a map with only 2 tiles produced 704 splines and an excessively dense road network.

### Main fixes

- the **Roads** layer no longer requests every `highway=*`;
- the OSM query is restricted to motor-road classes relevant to OMSI:
  - motorway / trunk;
  - primary / secondary / tertiary;
  - matching link classes;
  - unclassified / residential / living_street;
  - service;
  - road;
  - busway / bus_guideway;
- `footway`, `path`, `steps`, `cycleway` and `track` are no longer automatically converted to road splines;
- `service=parking_aisle`, `service=driveway`, `service=drive-through` and `service=emergency_access` are excluded from road reconstruction;
- `area=yes` ways are not treated as road centerlines;
- explicitly vehicle-denied ways are discarded;
- bus-specific `bus=yes|designated|permissive` access remains supported;
- the importer repeats this filtering even when the official OSM fallback returns the complete bbox.

### New geometry guard

Before each spline is written, the generator reconstructs its endpoint from:

`start position + rotation + length`

and compares it against the projected OSM endpoint.

If the error exceeds 2 cm, generation aborts and transactional rollback is triggered. This prevents future rotation/local-coordinate/serialization regressions from leaving runaway splines in the map.

### Tests

New regressions cover:

- non-motor way rejection;
- parking aisle and driveway rejection;
- dedicated bus access preservation;
- explicit motor-vehicle denial;
- physical continuity between consecutive generated splines;
- all previous tests remain enabled.
