# OMSI Map Studio v0.2.0-alpha.5-test.10.39-native

Native preview focused on fixing the loading overlay that could remain active even after roads and junctions had already been persisted and rendered.

## Identified cause

In the analyzed log, automatic generation completed successfully:

- complete OSM download;
- 2,626 graph segments;
- 2,167 persisted splines;
- 459 native OMSI curves;
- 116 persisted junctions;
- 0 skipped segments;
- 0 failed junctions.

The outer "Create real map" operation could still remain in a loading state because post-processing work continued before reaching the `finally` block that closes the overlay.

## Lighter final reload

After automatic roads are inserted:

- the viewport still receives the final snapshot;
- CARTO reference data is not downloaded/revalidated again because road insertion does not change georeference;
- the Explorer is not rebuilt while collapsed;
- the Explorer refresh is deferred until it becomes visible again;
- the create-map loading overlay is closed as soon as the final viewport reload completes.

## Timing diagnostics

`startup.log` now records:

- `ApplyMapSnapshot begin`;
- `viewport-ready elapsedMs=`;
- `reference-ready elapsedMs=` when applicable;
- `reference-refresh skipped`;
- `explorer-ready elapsedMs=`;
- `ApplyMapSnapshot complete elapsedMs=`;
- `Procedural roads final viewport reload begin/complete`;
- explicit loading-overlay closure after the final road reload.

This makes any remaining slow stage directly measurable.
