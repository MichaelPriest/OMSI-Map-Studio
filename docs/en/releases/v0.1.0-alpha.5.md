# OMSI Map Studio v0.1.0-alpha.5

Validation prerelease focused on the two most critical issues found after Alpha.4: **viewport flicker/reinitialization** and **unreliable map selection**.

## Main fixes

- the Babylon `Engine` stays attached to the canvas during normal React updates;
- structural `Scene` rebuilds use an atomic swap: the previous scene keeps rendering until its replacement is ready;
- camera actions — perspective, top, fit, focus and tile centering — no longer rebuild the whole scene;
- active-tile highlighting and the selection overlay are decoupled from structural rebuilding;
- selection is committed on left-button release, avoiding a React update halfway through the same click;
- visible objects and splines use real mesh picking;
- assets without a usable pickable mesh use screen-space tolerance for more predictable selection at different zoom levels;
- selecting an item no longer changes the selection filter or disarms **Move**/**Rotate**;
- a repeated quick click on the same item still centers/focuses it;
- **Move** and **Rotate** use a separate editing layer, so changing the selected item no longer rebuilds the whole map;
- the base visualization is temporarily hidden while the real editable copy receives the gizmo, then restored when editing ends;
- Snap continues to use the configured real values;
- the duplicate legacy `pointerup` selection fallback was removed;
- real spline surfaces, O3D objects, trees and fallback markers remain selectable.

## Expected behavior

The workflow is closer to the classic OMSI editor: choose a tool, click a map item directly, keep the tool active and edit the selected element without the scenery blanking or flickering during selection, asset streaming or Inspector opening.
