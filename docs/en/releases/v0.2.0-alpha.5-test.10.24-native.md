# OMSI Map Studio v0.2.0-alpha.5-test.10.24-native

Build **ALPHA 5 TEST 10.24 — additional CARTO reference NullReference fix**.

## Observed issue

Even after Test 10.23, some maps could still fail in **Map > Map reference over terrain...** with:

`NullReferenceException: Object reference not set to an instance of an object.`

Stage diagnostics showed the exception still occurred inside `LoadCartoReferenceAsync`, before the texture was sent to the viewport.

## Fixes

Test 10.24 hardens three areas:

- old/incomplete georeference files with a missing `mapType` are normalized to `roadmap`;
- `ValidateGeoreference` no longer calls `.Trim()` on a null `MapType`;
- a CARTO response without content now produces a controlled error instead of a `NullReferenceException`;
- the WIC fallback checks decoder/frame/converter for null before use;
- a `NullReferenceException` from the WIC fallback is contained instead of escaping the overlay flow.

## Compatibility

Maps created with earlier builds continue to open. Normalization happens in memory and preserves the existing georeference.

## Carried forward

This build keeps:

- Map Studio's own PNG decoder for CARTO;
- PNG signature validation;
- CARTO key storage in Windows Credential Manager;
- OSM fallback in the area picker;
- staged diagnostics;
- previous navigation and cache improvements.
