# OMSI Map Studio v0.2.0-alpha.5-test.10.73-native

## Test 10.73 — terrain-adaptive automatic bridge piers

This preview adds automatic structural supports to bridges generated by the procedural/OSM workflow.

- road runs resolved as bridges, including layer-only OSM cases with \`layer > 0\`, can now receive automatic piers;
- piers are distributed across the **continuous structural run**, using real spline links instead of restarting spacing for each segment;
- target span is approximately **30 m**, with end insets to keep supports away from transition ramps;
- placement follows both straight and curved spline geometry;
- pier height is calculated from the bridge deck underside down to the **real terrain** at each support position;
- very low clearances do not receive artificial supports;
- heights are quantized in **0.25 m** increments so matching variants can reuse the same asset;
- cap width follows the physical Road Kit profile width;
- every variant is a real Map Studio-generated **SCO/O3D** asset with procedural \`ms_bridge_concrete.bmp\` texture;
- identical height/width variants reuse the same generated asset;
- a pier generation/insertion failure does not roll back already-persisted road splines;
- tunnel runs never receive bridge piers;
- no \`.terrain\` file is modified;
- Core and Renderer tests cover O3D geometry, asset reuse, layer-only inference, distribution and terrain preservation.

Next structural steps: improve supports around elevated junctions, add tunnel portals, and finish visual road ↔ bridge/tunnel transitions.

Validation for this revision: Core, Renderer and the WinUI build must remain green before the preview is published.
