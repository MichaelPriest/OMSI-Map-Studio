# OMSI Map Studio v0.2.0-alpha.5-test.10.12-native

Build **ALPHA 5 TEST 10.12 — expanded real-map workflow, Tile XY, Copernicus and structural tile fixes**.

## Real-map area workflow

The real-map creator has evolved since Test 10.11:

- OpenStreetMap/Nominatim place search with rate limiting;
- adjustable area selection directly in the window;
- live tile-grid/size updates;
- three OSM road modes: no import, prepare preview, or generate;
- OSM road preview before any map write;
- corrected centering for both odd and even area sizes.

2×2, 4×4 and other even-sized areas now use the true geometric center of the grid instead of being offset by 150 m.

## Expanded Tile XY

The **Tile XY** window now brings together:

- the map tile list;
- focus/load for the selected tile;
- safe creation and deletion;
- access to available tile properties;
- navigation without requiring Inspector.

Creating or deleting a tile no longer forces the camera to a new position; the current navigation state is preserved.

## Group duplication

Multiple selection can be duplicated through a safe batch operation. If the new object identities cannot be confirmed, the operation is rolled back instead of leaving a partial duplicate.

## Open-Meteo / Copernicus elevation

The real-map workflow now supports **Open-Meteo / Copernicus** elevation in addition to the existing Google provider.

- user credentials are kept in Windows Credential Manager when required;
- the provider is selected in the real-map window;
- provider attribution is shown in the UI.

## Structural OMSI tile-grid correction

This Test consolidates OMSI tiles on one canonical **300 m** grid:

- negative X/Y coordinates use floor-based conversion;
- renderers and projections reuse the same grid math;
- `global.cfg` correctly persists 3×3 grids with negative coordinates;
- new `.terrain` edges are copied from direct neighbors;
- all four diagonal neighbors are also considered for shared corner vertices;
- an on-disk round trip reopens the map through Core and checks every shared 3×3 edge;
- area creation and manual tile creation use the same math.

Diagonal-neighbor handling fixes a case where two tiles could represent the same world-space corner with different heights before the intermediate tile was created.
