# OMSI Map Studio v0.2.0-alpha.5-test.10.136-native

## Test 10.136 — stock equivalents for Brazilian R-1 and R-2 signs

Test 10.136 continues the explicit-sign reconstruction introduced in 10.135 and adds a deliberately narrow semantic compatibility layer for Brazilian maps.

Brazilian OpenStreetMap documentation relates:

- `R-1` to **mandatory STOP**;
- `R-2` to **GIVE WAY / yield**.

Because original OMSI stock sign families use European/German sign assets, Map Studio now permits a stock equivalent only where shape and meaning are directly compatible:

- `BR:R-1` → STOP asset / `206` family;
- `BR:R-2` → GIVE WAY asset / `205` family.

### Safe matching

The translation is intentionally restricted. Other Brazilian sign codes are not converted automatically.

For example:

- `BR:R-3` does not map to an arbitrary German `VZ_*`;
- codes without a known safe equivalent remain unmatched for review/fallback;
- custom assets whose names already contain the explicit Brazilian sign reference remain eligible normally.

This prevents a Brazilian sign from receiving a visually incorrect asset merely because both belong to the generic traffic-sign category.

### Round-trip

The integration regression creates both:

- a `traffic_sign=BR:R-1` node;
- a `traffic_sign=BR:R-2` node;
- local `VZ_206.sco` and `VZ_205.sco` assets.

The batch runner must place both stock-equivalent objects in the OMSI tile without reporting either as a missing asset.

### Preserved regressions

Test 10.136 also preserves rejection of `BR:R-3`, safe `DE:206` and `DE:274-30` matching, absolute and way-relative orientation, ambiguity protection, OSM cache v3, and all previous 10.121–10.135 gates.
