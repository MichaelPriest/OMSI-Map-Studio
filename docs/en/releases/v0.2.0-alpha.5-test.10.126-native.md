# OMSI Map Studio v0.2.0-alpha.5-test.10.126-native

## Test 10.126 — deeper manual-tools audit

This build continues the audit started in 10.124 and fixes the difference between an **implemented handler** and a tool that is **actually reachable from the visible editor UI**.

### Real visible manual routes

The audit confirmed the old `MapToolPalette` remains hidden by design. Accessibility is therefore enforced on the current editor surface:

- **Selection → Validate map**: new visible entry point for Validation;
- **Objects → Infrastructure**: opens Utilities;
- **Roads → More → Tunnel creator**: opens the real tunnel generator;
- **Transport → Stops and terminals**: opens Transit Assets.

Legacy palette buttons remain hidden and are no longer treated as evidence that a tool is user-accessible.

### Portuguese asset classification

The Library now recognizes Portuguese asset names that could previously fall into **Other**:

- transit: `ponto`, `parada`, `abrigo`, `garagem`, `estacao`;
- utilities: `energia`, `agua`, `saneamento`, `esgoto`, `infraestrutura`;
- tunnels: `tunel`.

Regression cases were added for **Stops / shelters**, **Water / sanitation**, and **Tunnels**.

### End-to-end persistence checked

The audit verified start → interaction → write → reload for the remaining focus areas:

- Transit Assets/Utilities → real SCO insertion into `.map`, transactional backup and tile reload;
- placed spline/tunnel → real `.map` insertion and reload;
- tunnel generator → real `.sli` + textures + backup + `OmsiSplineDefinitionReader` read-back;
- junctions → geometric target → SCO placement → real commit;
- Track → `.ttr` + backup + reload;
- StationLink → `StnLinks.cfg` + backup + reload;
- traffic-light programs → `.sco` + backup + reload;
- SCO/SLI paths → real patch + backup + reload;
- Validation analyzes dependencies, TTData, links and map structure; repair actions continue through real writers.

### Regression protection

Native Windows CI and Native Preview Release now verify the **real visible routes**, plus persistence handlers, writers and readers.
