# OMSI Map Studio v0.2.0-alpha.5-test.10.115-native

## Test 10.115 — physical-tile OSM coverage + animated loading

This build fixes the case where real-map generation could finish with tiles only.

### Root cause fixed

OSM reconstruction used the geographic rectangle drawn by the user, while created OMSI tiles always occupy physical 300 × 300 m blocks. With very thin selections, the app could create full tiles but query only a few meters of geographic height or width. That could return little or no reconstructable content.

The OpenStreetMap query now uses the union of the user selection and the real geographic coverage of every created tile. Roads, junctions, buildings, vegetation, street furniture and infrastructure are therefore requested for the complete physical map area.

### Empty success is no longer accepted

- zero OSM elements now fail explicitly;
- OSM data that produces zero placed roads/junctions/structures/objects also fails;
- diagnostics include nodes, ways, relations, ignored roads, out-of-map segments, missing node references and review items;
- rollback remains enabled;
- a zero-placement generation can no longer be marked Completed.

### Loading and animation

- the loading overlay stays visible through the entire reconstruction;
- animated ProgressRing;
- indeterminate progress during downloads and determinate progress when known;
- current stage and percentage;
- tile-creation progress;
- live pipeline messages;
- Cancel generation button directly on the overlay;
- an animated ProgressRing also appears on the wizard Progress page.
