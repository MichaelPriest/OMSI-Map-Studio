# OMSI Map Studio v0.2.0-alpha.5-test.10.28-native

Native preview focused on making the CARTO/OpenStreetMap reference behave like a terrain layer instead of a physically lifted second surface.

## Coplanar terrain reference

Test 10.27 fixed mosaic clipping, but the reference was still generated as a second mesh with a physical `+0.08 m` height offset. At some viewing angles or terrain shapes this could make the imagery disappear behind the terrain or produce depth conflicts.

This version:

- removes the physical `+0.08 m` lift;
- each reference triangle reuses the exact OMSI terrain-cell corner heights;
- reference triangulation follows the same diagonal/order as the terrain geometry;
- imagery follows elevated, deformed and sloped terrain without floating above it;
- the layer is rendered after terrain using depth-read without depth writes;
- a dedicated D3D11 rasterizer applies `DepthBias` and `SlopeScaledDepthBias`, visually pulling the decal forward without modifying Y coordinates;
- the reference sampler uses a transparent border, allowing edge cells to keep exact terrain geometry without stretching/repeating image pixels;
- the reference remains outside picking;
- mosaic streaming, Voyager, opacity, visibility toggle and CARTO/OpenStreetMap attribution are preserved.

## What to validate

1. Open the same map used for the Test 10.27 screenshots.
2. Enable the map reference.
3. The imagery should be visible directly on the terrain mesh rather than appearing buried underneath it.
4. Tilt and zoom the camera to check for visible z-fighting.
5. Test elevated or irregular terrain: imagery should follow the relief exactly without an 8 cm or 35 cm physical lift.
