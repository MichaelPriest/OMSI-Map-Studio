# OMSI Map Studio v0.2.0-alpha.5-test.10.128-native

## Test 10.128 — roads use installed OMSI assets

This build fixes road-spline selection during automatic reconstruction. Test 10.121 already introduced physical matching, but many real OMSI assets never reached that resolver because candidate discovery depended too heavily on file names.

### Changes

- common OMSI names such as `str_2spur_...` and `fahrbahn` are recognized as roads;
- splines classified as **Other** can also be candidates when their real `.sli` content proves they are driveable;
- the resolver reads surfaces and `[path]` sections and requires vehicle traffic paths;
- one-way status is also inferred from actual path directions;
- `MapStudio_*` assets are excluded from the **installed OMSI asset** candidate set, preventing the Road Kit from being counted as an OMSI match;
- the analysis limit was expanded for larger installations;
- when a physically compatible installed OMSI SLI exists, that path is written to the `.map`;
- the Road Kit remains a fallback only when no compatible installed spline is available.

### Generation evidence

Progress now reports separately:

- road segments using an **installed OMSI SLI**;
- road segments that required the **Road Kit fallback**.

### Regression coverage

A full round-trip regression test simulates an installed `Splines\Marcel\str_2spur_11m.sli`, reconstructs the road, writes the tile, and verifies the resulting `.map` references the installed SLI instead of `MapStudio_RoadKit`.

Installed junction SCOs remain cataloged only in this build. They are not automatically substituted until their connection points and fit can be validated safely.
