# OMSI Map Studio v0.2.0-alpha.5-test.10.121-native

## Test 10.121 — installed OMSI library in real-world reconstruction

Test 10.121 starts safely reusing assets already installed with OMSI during real-world map reconstruction.

### Installed OMSI roads

- the real-world catalog now indexes **Splines + Sceneryobjects**;
- installed road splines are measured from their actual `.sli` physical profile;
- only candidates containing OMSI traffic paths are considered;
- physical width, traffic path count, pedestrian paths and one-way/divided naming hints contribute to matching;
- ordinary ground-level roads may prefer a compatible installed OMSI spline;
- when no sufficiently compatible candidate exists, the **MapStudio Road Kit** remains the fallback;
- bridges and tunnels remain on the Road Kit at this stage to avoid incompatible structural variants.

### Junctions, signals and crossings

The installed library now recognizes dedicated candidates for:

- junctions/intersections/roundabouts;
- traffic signals, including traffic light, Ampel and Signalgeber naming;
- pedestrian crossings / zebra crossings / Zebrastreifen;
- road splines.

Generation progress reports how many compatible construction assets were recognized.

### OpenStreetMap

The Furniture layer now also acquires:

- `highway=traffic_signals`;
- `highway=crossing`;
- nodes carrying a `crossing=*` tag.

The OSM cache schema was bumped so older cached Furniture chunks do not hide the newly requested elements.

Traffic signals are now a dedicated reconstruction feature and can match an installed `.sco`. Crossings are kept conservative when orientation is not trustworthy, preventing randomly rotated zebra markings.

### Next stage

Installed junction `.sco` files are cataloged but are not blindly inserted until their connection geometry can be validated. Once reference assets are available, their connection conventions can be analyzed and an original Map Studio junction/signal/crosswalk kit can be generated around compatible dimensions and behavior.
