# OMSI Map Studio v0.2.0-alpha.5-test.10.142-native

## Test 10.142 — continuous OMSI road curves and terrain-to-road conform

Test 10.142 fixes the two visual issues reported after 10.141: terrain intersecting/floating relative to roads and regular cracks along curved sections.

### Real curves instead of a chain of straight chords

The automatic reconstructor no longer writes every OSM segment with `radius=0`.

When two consecutive segments belong to the same road, use the same profile, share a degree-2 node and form safe geometry, Core now:

- fits the circle through start, control node and end;
- resolves tangent rotation, signed OMSI radius, arc length and sweep;
- rejects radii that are too tight for the physical road width;
- limits arcs to safe sweeps;
- validates the calculated physical endpoint before writing the `.map`.

When a circular fit is not valid, the safe straight geometry is retained.

### Terrain conform after road placement

DEM elevation is still applied first, but a second pass now runs after road splines are generated.

For every ground road, the system:

- uses the position, start height, gradient, radius and physical width of the spline actually written;
- conforms terrain to the road corridor;
- keeps terrain about 12 cm below the road surface to avoid clipping/z-fighting;
- uses a feathered shoulder instead of abrupt terrain walls;
- follows the actual circular path for curved splines;
- excludes bridges and tunnels from ground-level conforming.

### Regression coverage

New tests verify:

- OMSI arc round-trip reaches its expected endpoint;
- a three-point OSM bend becomes a real curved spline;
- `radius` is persisted in `tile_0_0.map`;
- terrain under the road follows spline height;
- distant terrain remains unchanged;
- terrain backup is created before conforming.
