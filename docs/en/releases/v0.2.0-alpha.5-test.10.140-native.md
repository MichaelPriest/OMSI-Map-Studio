# OMSI Map Studio v0.2.0-alpha.5-test.10.140-native

## Test 10.140 — physically safe fitting for stock OMSI assets

Test 10.140 fixes issues visible in 10.139 where some stock junctions could be offset, physically oversized or overlap connected roads.

### Real logical center for stock junctions

The resolver no longer assumes that local `0,0` in a `.sco` file is the physical center of the intersection.

It now:

- reads vehicle `[path]` geometry from the object;
- estimates the logical center from its arms;
- refines the center from the fitted mouth lines;
- keeps that local-center offset in the match;
- compensates the object origin when writing it to the OMSI map.

This supports original junction objects whose pivot/origin is not located at the actual intersection center.

### Oversized junction rejection

Besides arm count, angles and width, the resolver now evaluates the physical scale of the junction.

A stock object whose mouths are too far from the center is rejected when it does not fit the scale of the target OSM roads. Installed road splines are preserved and only that node falls back to a generated junction, preventing giant overlapping intersection meshes.

### Stock-first with physical compatibility

The broadened stock-road tolerance introduced in 10.139 has been tightened.

Original OMSI remains the first choice, but a materially oversized or undersized stock spline is no longer selected merely to avoid fallback.

Selection remains:

1. physically compatible original OMSI;
2. nearest original OMSI inside a safe tolerance;
3. compatible installed addon;
4. Road Kit as the final fallback.

### Regression coverage

New tests verify:

- stock junction `.sco` with an offset local origin;
- logical junction-center calculation;
- origin compensation in the written `.map`;
- rejection of stock junctions physically too large for narrow roads;
- rejection of materially oversized stock splines for narrow roads;
- original-asset priority when physical compatibility is valid.
