# OMSI Map Studio v0.2.0-alpha.4-test.2-native

**TEST 2** build of the native WinUI 3 + Direct3D 11 architecture.

This version focuses on the terrain visibility issue found in Alpha.4 Test 1.

## Main fix

In Test 1, the `.terrain` file was read and its triangles were uploaded to the GPU, but the native pass still used the default Direct3D 11 rasterizer with back-face culling.

The React version already rendered terrain double-sided (`backFaceCulling = false`). Depending on the effective mesh/camera winding, the visible native terrain face could be culled. With the OMSI sky enabled this looked like a cloud texture on the ground, while the sky was actually visible through the grid.

Test 2 uses a dedicated `CullNone` rasterizer only during the terrain pass and restores the normal state immediately afterwards.

## Validate first

1. Open the same map where terrain looked like sky/clouds.
2. Confirm the terrain surface covers the background and follows the real `.terrain` elevations.
3. Confirm base `[groundtex]`, detail texture, and painted layers remain visible.
4. Toggle **Terrain** with `T`.
5. Test top and perspective camera modes.

Keeps all Alpha.4 Test 1 features: textured O3D objects, textured SLI splines, base/paint/detail terrain materials, DDS painting, day/night sky, ID-buffer selection, gizmos, Inspector, Explorer, asset library, copy/delete, link editing, leveling, fullscreen, filters, and native shortcuts.
