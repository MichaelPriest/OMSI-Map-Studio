# OMSI Map Studio v0.2.0-alpha.5-test.10.120-native

## Test 10.120 — Level / Lower / Raise working for selection and placement

Test 10.120 fixes the road elevation controls in the bottom toolbar.

### The problem

The toolbar exposed three main commands:

- `↓ Lower`;
- `Level`;
- `↑ Raise`.

They only changed the placement mode for the next spline. When an existing spline was selected in the viewport, the buttons appeared to do nothing.

Also, with `Snap: on`, the snapped endpoint replaced the computed elevation as well, which could cancel the selected Level/Raise/Lower mode when the road was finalized.

### Fixes

- with an existing spline selected and no active placement:
  - `↑ Raise` immediately moves the selected spline upward by the configured step;
  - `↓ Lower` immediately moves it downward;
  - `Level` sets both start/end gradients to zero;
- repeated Raise/Lower clicks now accumulate correctly;
- the toolbar indicator shows the selected spline's resulting elevation;
- during new-road placement, the same buttons still control the final elevation relative to the start point;
- changing elevation mode while previewing a road immediately rebuilds the preview geometry;
- `Snap: on` no longer overwrites the chosen elevation in Level/Raise/Lower modes;
- if a horizontally snapped endpoint differs vertically by more than 25 cm, horizontal snapping is kept but an invalid `Previous/Next` link is not created.

### Preserved behavior

Still preserved:

- Follow Terrain;
- snap and auto-connect;
- Easy Road;
- straight and visual curve modes;
- `[spline_h]`;
- undo/redo and pending edits;
- Test 10.119 OSM road filtering fixes.
