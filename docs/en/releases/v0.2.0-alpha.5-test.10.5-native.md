# OMSI Map Studio v0.2.0-alpha.5-test.10.5-native

Build **ALPHA 5 TEST 10.5 — map catalog close/crash fix**.

The Test 10.4 `startup.log` identified the actual process-closing bug: the adaptive `ContentDialog` helper tried to re-use a `FrameworkElement` that was already owned by the dialog and immediately assign it as `ScrollViewer.Content`, triggering WinUI **“Element is already the child of another element”**.

## Fix

- `AdaptiveContentDialogExtensions.Prepare()` now detaches the original dialog content first;
- only then is that element assigned to the adaptive `ScrollViewer`;
- the new `ScrollViewer` is then assigned back to the dialog;
- `OnOpenMapCatalogClick` now catches and logs failures to `startup.log`, preventing an `async void` exception from terminating the application.
