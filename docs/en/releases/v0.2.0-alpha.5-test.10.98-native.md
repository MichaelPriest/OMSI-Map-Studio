# OMSI Map Studio v0.2.0-alpha.5-test.10.98-native

## Test 10.98 — unified real elevation in the real-world map pipeline

This preview removes the hard-coded `Y = 0` assumption from the Core real-world reconstruction pipeline.

### Georeferenced DEM surface

A new elevation surface accepts:

- a height grid;
- south/west/north/east bounds;
- an optional vertical datum/base.

Sampling is bilinear. By default, the grid minimum becomes `0 m` in the OMSI map, preserving relative relief without shifting the whole world to a large absolute altitude.

### OMSI terrain

The new elevation batch:

- opens every `.map.terrain`;
- preserves the tile's native resolution;
- resamples the DEM into every terrain sample;
- naturally supports the standard OMSI 60×60 / 61×61 layout;
- writes through temporary files;
- creates a backup for each terrain;
- rolls back if a write fails.

### Shared vertical placement

The same elevation surface is now used by:

- road splines;
- junctions;
- infrastructure;
- buildings;
- trees/shrubs;
- street furniture.

Real terrain therefore no longer leaves generated scenery locked at `Y=0`.

### Transactional pipeline

A new `ApplyingElevation` stage runs before road generation.

The complete session snapshot now also includes `.map.terrain` files. If roads or scenery fail later, both terrain and tile configuration are restored.

### Tests

- 2×2 bilinear interpolation;
- minimum-value datum normalization;
- resampling into a standard 60×60 OMSI terrain;
- edge-value continuity;
- physical terrain backup.
