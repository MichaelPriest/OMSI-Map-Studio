# OMSI Map Studio v0.2.0-alpha.5-test.10.134-native

## Test 10.134 — prefer stock junctions with functional OMSI traffic-light control

Test 10.132 introduced stock traffic-signal and crossing placement from OSM. Test 10.134 improves selection of the original junction itself: when OSM marks an intersection as signalized, the resolver prefers a compatible stock junction that already contains native OMSI traffic-light logic.

### What counts as functional control

A stock candidate is considered functional when its own `.sco` contains:

- a native OMSI controller/program using `[traffic_lights_group]`, `[traffic_light]` and `[phase]`;
- at least one vehicle path of type `0` bound to that control through `[use_traffic_light]`.

No parallel traffic-light format is introduced. The existing OMSI scenery parser is used.

### Selection

Physical compatibility remains mandatory:

- matching arm count;
- existing maximum angular error;
- compatible mouth width;
- physically valid mouth/trim distance.

Only among candidates that already pass those requirements does a signalized OSM target prefer the asset with functional internal traffic control.

If no compatible functional junction exists, the previous behavior remains available: another geometrically compatible stock junction can still be used, external stock signal heads remain available, and the generated junction stays the final fallback.

### OSM propagation

`highway=traffic_signals` nodes and signalized crossings are associated with the nearest road-graph junction. That junction receives `PreferFunctionalTrafficControl=true` before installed assets are resolved.

### Regression coverage

Coverage now verifies two geometrically identical stock junctions with the plain asset sorted first, preference for the native traffic-controlled asset, propagation from a real OSM signal node through the road runner, map persistence of the functional junction, and `FunctionalStockTrafficControlledJunctionCount` reporting.
