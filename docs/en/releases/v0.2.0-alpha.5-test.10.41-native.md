# OMSI Map Studio v0.2.0-alpha.5-test.10.41-native

Native preview focused on the regression where automatic road creation could appear to loop during the OpenStreetMap/Overpass download.

## Confirmed cause

The renderer was not looping in the analyzed log. The initial 36-tile snapshot completed normally and the stall started only after OSM import began.

Overpass failure recovery could recursively subdivide each failed chunk to depth 3. One failed chunk could expand to as many as 85 recovery queries and every query could still try multiple servers with a long timeout. During HTTP 429/504 periods or slow endpoints this could turn a network failure into tens of minutes or hours of waiting.

## Fix

- recovery depth reduced to a single subdivision;
- one failed chunk can create at most 4 recovery sub-chunks;
- 2-minute global OSM import budget;
- independent 18-second timeout per endpoint;
- Overpass query timeout reduced to 16 seconds;
- endpoint starting order now rotates so every chunk does not hammer the same server first;
- completeness rule is preserved: incomplete areas do not generate partial automatic roads;
- startup.log now records every chunk, endpoint attempt, subdivision, success, failure and budget timeout;
- the UI also displays the current OSM download stage.

## Regression guard

A test now guarantees that a small area with one permanently failing endpoint is limited to 5 requests: 1 original chunk plus 4 recovery sub-chunks.
