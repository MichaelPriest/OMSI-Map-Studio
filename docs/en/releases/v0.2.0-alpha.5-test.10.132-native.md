# OMSI Map Studio v0.2.0-alpha.5-test.10.132-native

## Test 10.132 — stock traffic signals and crossings driven by OSM

Test 10.131 hardened original-junction mouth detection using the real `[path]` tangent. Test 10.132 combines that junction geometry with real OpenStreetMap control nodes to place original OMSI traffic signals and crossings.

### OSM control evidence

The road runner now reads real nodes tagged with:

- `highway=traffic_signals`;
- `highway=crossing`;
- `crossing=*`;
- `crossing:signals=yes`.

Those points are projected into the physical map coordinate system and associated with the nearby road junction.

### Stock traffic signals

When a compatible installed asset exists, Map Studio prioritizes original OMSI `Ampel_*` scenery objects. A signal node located at the junction center applies to all approaches, while an approach-specific OSM node only affects its matching arm.

Placement uses the real arm direction, stock-junction mouth trim, road width, roadside offset and approach-facing rotation.

### Stock crossings

OSM crossing nodes are matched to the corresponding junction arm. If an installed scenery-object crossing is available, such as original `Zebra_*`/crosswalk families, it is placed beyond the junction mouth and rotated across the road.

Spline-only crossing assets are intentionally not written by this scenery-object pass.

### No duplicate scene placement

Controls consumed by the road runner keep their original OSM feature identity. The scene reconstruction pass receives those IDs and skips only the already-consumed controls.

Standalone signals or crossings not consumed by a road junction remain eligible for the normal street-furniture reconstruction path.

### Regression coverage

Coverage verifies OSM control parsing/projection, a four-arm stock junction, four stock signals from one central signal node, one stock crossing on the correct arm, real tile persistence, procedural-junction absence when stock fitting succeeds, and selective duplicate suppression in the scene pass.
